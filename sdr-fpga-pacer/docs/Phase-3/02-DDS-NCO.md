# 2. Direct Digital Synthesis (DDS / NCO)

To mix a signal down to baseband (Digital Mixing), we need a continuous sine and cosine wave. In hardware, we generate these using a **Numerically Controlled Oscillator (NCO)** via a technique called **Direct Digital Synthesis (DDS)**.

## Architecture of a DDS

A DDS consists of two main components:
1. **The Phase Accumulator:** An N-bit counter that wraps around. It represents the phase angle from $0$ to $2\pi$.
2. **The Phase-to-Amplitude Converter:** Usually a Look-Up Table (LUT) stored in Block RAM (BRAM), mapping phase angles to sine/cosine amplitude values.

### The Mathematics

The Phase Accumulator is incremented every clock cycle by a Tuning Word ($M$).
$$f_{\text{out}} = \frac{M \cdot f_{\text{clk}}}{2^N}$$

Where:
- $f_{\text{out}}$ = The generated sine wave frequency.
- $f_{\text{clk}}$ = The FPGA clock frequency.
- $N$ = The bit-width of the phase accumulator.
- $M$ = The Phase Tuning Word.

**Example:** If $f_{\text{clk}} = 100 \text{ MHz}$ and $N = 32$ bits, the frequency resolution (how finely we can tune the oscillator) is:
$$\Delta f = \frac{100 \times 10^6}{2^{32}} \approx 0.023 \text{ Hz}$$
This incredible precision is why DDS is ubiquitous in radar and SDR.

## Spurious-Free Dynamic Range (SFDR)

A 32-bit phase accumulator has over 4 billion values. Storing a 4-billion entry LUT in FPGA memory is impossible. Therefore, we **truncate** the phase accumulator, using only the top $P$ bits to address the LUT.

- **Phase Truncation:** Using only the top $P$ bits creates phase noise (spurs in the frequency domain).
- **Amplitude Quantization:** Storing the sine wave with $D$ bits of amplitude resolution also creates quantization noise.

*Rule of Thumb:* The SFDR of your NCO is approximately $6 \times D$ dB, where $D$ is your amplitude bit width (e.g., a 16-bit LUT provides ~96 dB of SFDR).

## Verilog Implementation

Here is an exhaustive, synthesizable Verilog implementation of a DDS.

```verilog
module dds_nco #(
    parameter ACC_WIDTH = 32, // N: Accumulator width
    parameter LUT_ADDR  = 10, // P: Top bits used for LUT (1024 entries)
    parameter DATA_W    = 16  // D: Amplitude resolution (Q1.15)
)(
    input  wire                 clk,
    input  wire                 reset,
    input  wire                 enable,
    input  wire [ACC_WIDTH-1:0] tuning_word, // M
    output reg  signed [DATA_W-1:0] sine_out
);

    // 1. Phase Accumulator
    reg [ACC_WIDTH-1:0] phase_acc;

    always @(posedge clk) begin
        if (reset) begin
            phase_acc <= 0;
        end else if (enable) begin
            phase_acc <= phase_acc + tuning_word;
        end
    end

    // 2. Phase Truncation (Take top LUT_ADDR bits)
    wire [LUT_ADDR-1:0] lut_index;
    assign lut_index = phase_acc[ACC_WIDTH-1 : ACC_WIDTH-LUT_ADDR];

    // 3. Phase-to-Amplitude LUT (Inferred ROM)
    // Note: In reality, you initialize this with a $readmemh file generated by Python
    reg signed [DATA_W-1:0] sine_rom [0:(1<<LUT_ADDR)-1];
    
    initial begin
        $readmemh("sine_lut.hex", sine_rom);
    end

    // 4. Register the Output (Pipelining for f_max)
    always @(posedge clk) begin
        sine_out <= sine_rom[lut_index];
    end

endmodule
```
